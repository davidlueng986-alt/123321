## Objective / method
Independently audit E016 with a **standalone Python implementation** that enumerates all `n!` row-column permutations, retaining those with distinct A symbols. The E016 code instead calls the project's DFS-based `transversals_single`. Implement a fresh cycle-based two-symbol Latin-trade generator, and exact-cover search for B as a partition into disjoint A-transversals. For each selected B class T, any third-square C-symbol class U must satisfy `|T∩U|=1`. If the remaining compatible U fail to cover even one cell, that B prefix is impossible. Every B-partition is searched unless an explicit budget exception yields `UNKNOWN_BUDGET`. This necessary-condition pruning is sound but does not produce a proof certificate by itself.

Inputs: the public Egan–Wanless A in `near_triple.json`, the historical Parker A in `parker_pair.json`. Reproduction: `python E017_replay.py --nodes 500000 --seconds 30 --output E017_REPLAY_RESULTS.json` or import `audit`, `cases` from that file to run cases individually. Published per-case data: `E017_RESULTS.json`. Source code: `E017_replay.py`; regression tests: `test_E017_replay.py`. No external solver or GPU.

## Actual results
- **Independent E016 audit:** Egan original A reproduced exactly 1080 A-transversals, **24,875 nodes / 18,407 support prunes**, exhaustive fixed-A UNSAT. Independent cycle-generator trade12 reproduced **904 transversals, 17,377 / 13,324**, exhaustive fixed-A UNSAT. Both match E016 despite a separate implementation and seed 17.
- **NEW Parker first-square exclusion:** historical Parker A, **1104 transversals, 49,199 nodes / 37,286 prunes**, exhaustive fixed-A UNSAT. This excludes any triple containing that *specific first square*, stronger in scope than excluding the historical Parker A/B pair. Its 1104 transversal count differs from original Egan A (1080) and all 48 Egan one-trade variants (840–1000), hence is not paratopic to those 49.
- **NEW 12 Parker one-trade first squares:** indices `0,1,2,3,10,15,20,30,40,50,60,65` from the deterministic cycle generator, each individually exhausted and UNSAT_FIXED_A_EXHAUSTIVE. Example Parker trade65: **1272 transversals, 186,150 nodes / 140,325 prunes**, full exhaustion. This count is also distinct from the earlier 49 and original Parker A.
- **NEW 4 Egan disjoint two-trade first squares:** pairs of single-trade indices `(0,1),(0,20),(0,21),(0,22)`, distinct labeled matrices not among E016's 49, each exhausted and fixed-A UNSAT. Counts respectively **948, 864, 836, 780** A-transversals. Generator found **774 distinct labeled** Egan disjoint-two-trade matrices but only these four were tested; no claim for the other 770.
- **Total new completed fixed-A exclusions: 17** (1 Parker + 12 Parker trades + 4 Egan two-trades); **2 earlier E016 cases independently replayed**. Sum over the 17 new cases: **534,187 DFS nodes / 407,293 support-pruned nodes**. No candidate triple and no unrestricted nonexistence proof.
- **Positive control:** explicit order-4 GF(4) three-square construction independently verified Latin + overlays **16/16/16**; the fixed-A support solver returned `SAT_SUPPORT_ONLY`. A SAT_SUPPORT_ONLY result at order 10 would require independent completion and 100/100/100 verification.
- Parker A and Parker trade65 were rerun with a different seed (1 vs 17); both yielded the same exhaustive status and counts. All published per-case fixed-A searches finished below 500,000 nodes and the stated 30–60s case budget. The per-case outcomes are exhaustive **for each given A**.

## Failures and uncertainty
Two attempts to run all cases in one long local process hit the *outer execution timeout* after logging 17 completed cases, without writing the aggregate output. This is a **batch-run failure**, not an UNSAT proof and not evidence of a timeout for the individually completed cases; the missing cases were separately run and logged. Future replay should use case-by-case checkpoints or a longer outer timeout. A separate SAT/DRAT/FRAT or formal certificate has **not** been generated; both independent programs use the same exact-once mathematical lemma. Individual labeled input hashes differ, but full isotopy/paratopy classification and novelty relative to the published literature have not been established. No general symmetry coverage.
